## Что было найдено при аудите 2026-03-26

### Git

- локальный и серверный репозиторий `centrlp.ru` используют `origin = git@github.com:Makselyanov/centrlp2026.git`
- bare-репозитория вида `/home/deploy/git/centrlp.git` для этого сайта сейчас нет
- значит основной сайт не находится в той же схеме личного server-side git, что `crm`, `aamx`, `svrq`, `lapadom`

### Состояние сервера

- в `/var/www/centrlp` найден dirty working tree
- сервер содержит незакоммиченные изменения
- это означает, что часть актуального состояния сайта существует только на сервере

### Автоматизация

- в репозитории есть `.github/workflows/static.yml`
- workflow ориентирован на GitHub Pages
- фактический продакшн при этом обслуживается nginx с вашего VPS

Итог: сейчас у сайта нет одной прозрачной, документированной и безопасной схемы публикации.

## Как сайт раздаётся сейчас

`nginx` использует:

- `root /var/www/centrlp/dist`
- `try_files $uri $uri/ /index.html`

Это обычная схема для Vite SPA:

1. проект собирается в `dist`
2. nginx раздаёт `dist`
3. React Router внутри обрабатывает маршруты

## Что считать текущим источником правды

На момент аудита источником правды фактически является не GitHub и не локальная папка, а server working tree:

- `/var/www/centrlp`

Именно из него была восстановлена локальная копия `G:\mvp\centrlp`.

## Риски текущей схемы

- можно потерять изменения, если на сервере что-то правилось вручную
- GitHub `origin/main` не гарантирует совпадение с продом
- невозможно уверенно откатиться
- непонятно, какой именно коммит реально опубликован
- сложно автоматизировать SEO- и контент-процессы

## Целевое состояние

Если хотим привести сайт к вашему стандарту "личный git на сервере, не GitHub", рекомендую такую схему:

1. Создать bare-репозиторий на сервере, например `/home/deploy/git/centrlp.git`.
2. Зафиксировать актуальное состояние `G:\mvp\centrlp` в git.
3. Переключить `origin` с GitHub на личный репозиторий на `90.156.168.115`.
4. Убрать прямые правки в `/var/www/centrlp`.
5. Деплоить либо через `git push` + `post-receive`, либо через controlled `git pull` в working tree.
6. Отдельно описать build-step: `npm install` -> `npm run build`.
