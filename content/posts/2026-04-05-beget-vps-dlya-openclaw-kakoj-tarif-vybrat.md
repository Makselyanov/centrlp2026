# Beget VPS для OpenClaw: какой тариф выбрать в 2026 году

Когда мы в **CentrLP** только начинали запускать OpenClaw для клиентов, главный вопрос был: какой минимальный VPS вытянет агента в проде? Сэкономишь — получишь падения по OOM. Возьмёшь с запасом — переплатишь в 3–4 раза. После полугода эксплуатации на разных тарифах [Beget](https://beget.com/p7257) у нас сложилась чёткая картина: какой тариф под какую задачу.

В этой статье — практическое сравнение пяти VPS-конфигураций Beget применительно к OpenClaw. Без маркетинговой воды, только реальные цифры с боевых серверов.

## Что важно для OpenClaw

OpenClaw — это Node.js-приложение с долго живущим процессом, которое:

- **ест RAM** — Node.js-агент в покое держит 250–400 МБ, под нагрузкой может прыгнуть до 1.2 ГБ;
- **редко грузит CPU** — пики случаются на компиляции TypeScript и при анализе больших файлов, среднее использование 5–15%;
- **не любит медленные диски** — на HDD холодный старт занимает секунды, на NVMe SSD — миллисекунды;
- **жадный до сетевого трафика** — каждый ответ Claude/GPT — это 5–50 КБ туда и до 200 КБ обратно;
- **боится OOM-killer** — если RAM закончится, ядро Linux убьёт процесс, а перезапуск через `pm2` потеряет состояние сессии.

Это значит, что главные критерии выбора — **RAM** и **тип диска**. CPU и трафик — вторичны.

## Сценарий 1. Знакомство и тестирование — VPS S (230 ₽/мес.)

**Конфиг.** 1 vCPU, 1 ГБ RAM, 20 ГБ NVMe.

**Подходит для:** разработчиков, которые хотят попробовать OpenClaw, MVP-проектов, домашних экспериментов, хобби-ботов.

**Боевые наблюдения.** Один агент OpenClaw без n8n спокойно живёт в 600–800 МБ при условии, что вы не подключаете тяжёлые MCP-серверы. Холодный старт — 2 секунды. CPU простаивает 90% времени.

**Где будет больно.** Как только подключите n8n + лёгкую SQLite-БД, RAM закончится. OOM-killer прилетит на первой же сложной задаче. Решение — добавить swap-файл на 2 ГБ:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

Со swap'ом VPS S вытягивает связку OpenClaw + n8n, но станет заметно медленнее.

**Вердикт.** Берите для тестов и экспериментов. Зарегистрироваться можно по [нашей ссылке Beget](https://beget.com/p7257) — будет бонус на первый платёж.

## Сценарий 2. Боевой запуск под малый бизнес — VPS M (460 ₽/мес.)

**Конфиг.** 2 vCPU, 2 ГБ RAM, 40 ГБ NVMe.

**Подходит для:** одного работающего агента в проде, контент-завода для одного-двух клиентов, чат-бота на 100–300 диалогов в день.

**Боевые наблюдения.** Это **минимальный честный тариф для прода**. У нас на нём крутится связка:

- 1 × OpenClaw (Claude Opus 4.6, ~250 МБ);
- 1 × n8n (~400 МБ);
- 1 × PostgreSQL 16 (~150 МБ);
- 1 × Nginx + Certbot (~30 МБ).

Среднее использование RAM — 1.1 ГБ из 2. Резерв 900 МБ покрывает пики на сложных задачах. CPU стабильно на 8–12%.

**Где будет больно.** При попытке поднять второго агента OpenClaw параллельно. RAM моментально упирается в 1.9 ГБ, и второй процесс начинает тормозить.

**Вердикт.** **Оптимум по соотношению цена/качество.** Если вы запускаете OpenClaw под реальный бизнес — берите M, не экономьте 230 ₽. [Заказать VPS M на Beget](https://beget.com/p7257).

## Сценарий 3. Несколько клиентов на одном сервере — VPS L (880 ₽/мес.)

**Конфиг.** 2 vCPU, 4 ГБ RAM, 60 ГБ NVMe.

**Подходит для:** агентств, которые ведут 3–5 клиентов через один общий VPS, или одного клиента с серьёзной нагрузкой (1 000+ задач в день).

**Боевые наблюдения.** На L спокойно живут 2–3 параллельных агента OpenClaw + общий n8n + PostgreSQL + Redis. Свободной RAM хватает на пики.

**Где будет больно.** CPU всего 2 vCPU, и при одновременном пике у двух клиентов начинаются микро-задержки. На большинстве реальных нагрузок это незаметно.

**Вердикт.** Для агентств — рабочий минимум. Если у вас 5+ клиентов или один клиент с интенсивной нагрузкой — берите XL.

## Сценарий 4. Серьёзный прод — VPS XL (1 760 ₽/мес.)

**Конфиг.** 4 vCPU, 8 ГБ RAM, 120 ГБ NVMe.

**Подходит для:** контент-завода на 5–10 клиентов, e-commerce с интеграциями, систем с большой базой и параллельными агентами.

**Боевые наблюдения.** На XL у нас сейчас крутится прод-инфраструктура CentrLP: 4 агента OpenClaw, n8n с 50+ workflow, PostgreSQL с базой 8 ГБ, Redis, Nginx, регулярные бэкапы. Использование RAM — 4.5–5.5 ГБ, CPU — 15–25% в среднем.

**Вердикт.** Если OpenClaw — это ваш основной инструмент монетизации, экономить на RAM глупо. XL — это «забыть и работать».

## Сценарий 5. Максимум мощности — VPS XXL (3 520 ₽/мес.)

**Конфиг.** 6 vCPU, 16 ГБ RAM, 240 ГБ NVMe.

Берите только если у вас уже упёрлись в потолок XL, либо если планируете локально хостить open-source LLM (что для OpenClaw редкий кейс — обычно используют API Claude/GPT).

## Что ещё учесть

**Резервные копии.** Beget предлагает автоматические бэкапы за +20% к стоимости VPS. Для прода **включайте обязательно** — потеря состояния OpenClaw + базы n8n восстанавливается долго и больно.

**Снапшоты.** Перед каждым обновлением Node.js или OpenClaw делайте снапшот через панель Beget. Откат занимает 30 секунд.

**Мониторинг RAM.** Поставьте `htop` и `pm2 monit`. Если использование RAM регулярно превышает 80% — берите тариф на ступень выше.

**Гео.** Для российских клиентов — Москва. Если работаете с иностранцами — у Beget есть и зарубежные локации.
